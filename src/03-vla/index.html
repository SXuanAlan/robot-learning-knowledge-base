1VLA 是什么，“基础模型”又指什么VLA interfaces and the meaning of foundation models

VLA 把视觉、语言和机器人动作放进同一个学习系统。难点不在于让模型听懂一句话，而在于把这句话的意思落实到这台机器人的动作坐标、控制频率和闭环反馈上。Robot foundation model 则更强调：在多种任务、场景或本体上 Pretraining 之后，能适配到新的情况。VLA 说的是输入输出的形式，foundation model 说的是训练规模和迁移能力，两者不完全是一回事。

A VLA connects vision, language and robot actions. Semantics must become commands in the current body’s coordinates, timing and feedback loop. “Robot foundation model” additionally emphasizes pretraining and adaptation across tasks, scenes or bodies. VLA names an interface; foundation model names a training and transfer role.

如果语言模型只输出代码或调用现成的技能，它更接近 Agentic Robotics；如果同时预测未来视频和动作，就和 World Action Models 重叠了。这些分类描述的是系统在哪一层学习和推理，并不是互相排斥的公司阵营。

A language model that emits code or calls skills sits closer to Agentic Robotics. Joint future-video/action prediction overlaps with World Action Models. These categories locate learning and reasoning inside a system, rather than dividing companies into exclusive camps.

最初的 OpenVLA 把 SigLIP 和 DINOv2 的视觉特征接到 Prismatic / Llama 2 骨干上，每个动作维度离散成 token 输出。好处是能直接用上大规模 VLM 和混合的机器人数据；代价是动作 token 只能一个个串行生成，精度也受量化方式影响。原版和后来的 OFT recipe 要分开看，不能一提 OpenVLA 就以为所有版本都是逐个 token 自回归。

Original OpenVLA combines SigLIP and DINOv2 features with a Prismatic/Llama 2 backbone and discretized action outputs. This reuses VLM and mixed robot data, while introducing sequential decoding and quantization choices. Its original interface differs from later OFT recipes; not every derivative uses the same action decoder.

Octo 说明，通用机器人策略不一定非得是一个巨大的语言模型：用模块化的 token、mask 和动作头，同样能适配不同的传感器和机器人 [73]。比较模型时，参数量、Pretraining 数据、输入信息和 Post-training 预算应该一起列出来。

Octo illustrates that a generalist robot policy need not be a very large language model. Modular tokens, masks and heads also support heterogeneous sensors and adaptation [73]. Compare parameter count alongside training data, observations and adaptation budget.

RT-1、RT-2 与 RDT-1B：三种不同起点RT-1, RT-2 and RDT-1B: three different starting points

RT-1 [111] 用大规模机器人示范学习以指令为条件的动作序列；RT-2 [71] 更进一步，把网络上的视觉语言知识和机器人动作 token 放在一起训练。RDT-1B [112] 则针对双臂操作用了 diffusion transformer，输入语言、视觉和本体状态，用统一的动作表示输出连续动作序列。三者的侧重点分别是：从机器人序列中学习、迁移 VLM 的知识、把动作生成模型做大。都接受语言输入，不代表架构相同。

RT-1 [111] learns action sequences from large robot datasets; RT-2 [71] co-trains web vision-language knowledge with action tokens. RDT-1B [112] uses a diffusion transformer for bimanual manipulation with language, vision, proprioception and a unified action format. Language conditioning alone does not make these robot-sequence, VLM-transfer and generative-action approaches architecturally equivalent.

OpenVLA-OFT 的做法是并行解码、action chunking、连续动作表示加 L1 loss [74]。这是一个很好的反例：生成模型表达能力更强，不代表在任何数据集和算力预算下都比回归头好。反过来，回归头在某个有限的 benchmark 上表现好，也不能说明建模多峰分布没有意义。

OpenVLA-OFT combines parallel decoding, chunking, continuous actions and L1 regression [74]. Greater generative expressivity does not guarantee better results for every dataset or compute budget. Conversely, strong regression performance on a constrained benchmark does not make multimodal modeling unnecessary.

Flow Matching 里的 t 是生成过程的时间，和 action chunk 里机器人执行的时间是两回事，不要混淆。同样一个 50 步的 chunk，可以用不同的采样步数生成。具体公式以及和 Diffusion 的关系，见 Manipulation 一页的对照。

Flow time belongs to the generative process; robot time indexes the action chunk. A 50-step action sequence can be generated with different numbers of solver evaluations. See the manipulation comparison for precise conventions.

4π₀：VLM 与连续动作专家π₀: a VLM and continuous action expert

π₀ [5] 把 PaliGemma 的视觉语言知识接到了连续动作生成上：较大的 VLM 处理图像和文字，较小的 action expert 处理机器人状态和带噪声的动作，两类 token 通过注意力交互。这里的 expert 指的是专门处理某类输入的一组参数，并不是按任务挑选的一堆独立专家。

π₀ [5] connects PaliGemma’s vision-language knowledge to continuous actions. A larger VLM processes images and text while a smaller action expert handles robot states and noisy actions, interacting through attention. “Expert” here refers to specialized parameters for token types, not a library of separately selected task policies.

输入、输出与训练阶段Inputs, outputs and training stages

输入是多路相机图像、任务指令和本体状态；输出是一段连续的 action chunk，而不是用文字写出每个关节的数值。Flow matching 学的是怎样把一段噪声一步步变成符合当前观测的动作序列。机器人每次只执行这段计划的一部分，就重新观测一次，所以生成时的积分步数、chunk 长度和闭环查询频率是三个不同的量。

Inputs combine camera views, instructions and proprioception; the output is a continuous action chunk. Flow matching turns noisy actions into an observation-conditioned sequence. Replanning after executing a prefix separates solver steps, chunk horizon and observation-feedback rate.

原论文把跨机器人的 Pretraining 和针对任务的 Post-training 分开：Pretraining 打下可迁移的行为基础，Post-training 再用更有针对性的高质量数据提升精细或长流程任务。看演示视频时，要确认用的是 base policy 还是专门 Post-training 过的策略。另外，共用一个 VLM、把 tensor 形状统一，并不意味着动作的含义也统一了：关节目标、末端坐标、夹爪控制和机器人尺寸仍然要对齐。

The original report separates cross-robot pretraining from task-specific post-training. The former provides a reusable behavioral base; the latter improves demanding tasks using targeted data. Distinguish these checkpoints when reading demos. Shared representations do not make joint targets, end-effector frames, gripper commands or body geometry identical.

5π₀.₅：数据配方、两阶段训练与分层推理π₀.₅: data mixtures, two-stage training and hierarchical inference

π₀.₅ [44] 要解决的是在没见过的环境里完成多步骤操作，而不只是换一个更强的动作头。和 π₀ 相比，它多了三样东西：混合多种来源的数据，先离散后连续的训练安排，以及先出文字子任务、再出底层动作的分层推理。本节按数据、训练、推理三部分展开，架构细节对应原论文的 Fig. 3 和 Fig. 18。

π₀.₅ [44] targets multi-stage manipulation in unseen environments, beyond changing the action head. Relative to π₀, it combines heterogeneous data, discrete-to-continuous training and hierarchical text-to-action inference. This section separates data, training and inference, with architecture details shown in the original Figures 3 and 18.

第一阶段 97.6% 的训练样本都不是目标移动机器人的家务数据 [44]。这说明它的训练配方很依赖跨来源迁移，但不能理解成“机器人数据只要 2.4% 就够了”：其余数据里也有大量其他机器人的数据，而且采样比例并不等于小时数，更不等于信息量。论文用环境数量和数据来源的消融实验检验了迁移效果；不同来源的数据，对完成任务和听从语言指令的帮助也不一样。

In the first stage, 97.6% of sampled examples do not come from the target mobile-household source [44]. This is not a claim that robot data is only 2.4%: other sources include robots, and sampling proportions are not hours or causal information contributions. Environment-count and source ablations examine transfer, with effects differing between task progress and language following.

两阶段训练：FAST 负责离散监督，Flow 负责连续动作Two-stage training: FAST supervision and continuous flow actions

Pretraining 阶段把文字、定位结果和用 FAST 编码的动作统一成离散序列，用 next-token loss 学一个共享的表征。Post-training 阶段再加入一个随机初始化的 flow action expert，同时保留离散监督，让连续控制和语义能力一起适配。FAST [45] 在时间维上做 DCT 再压缩 token，去掉动作里的冗余；它改变的是训练时的表示，部署时并不需要自回归地吐出全部动作 token。

Pretraining unifies text, localization and FAST-encoded actions as discrete sequences. Post-training adds a randomly initialized flow action expert while retaining discrete supervision. FAST [45] uses temporal DCT and token compression to reduce action redundancy; the training representation does not require autoregressive action-token deployment.

上式是两个阶段分工的简写，Flow 的时间方向沿用本站统一的约定（从噪声到动作）。原作还用 adaptive RMSNorm 把 flow 时间注入专家层。最关键的是哪些 token 能看到哪些信息：动作专家可以看图像、prompt、状态前缀和其他专家 token，但不能看 FAST 编码的动作答案，否则训练时就把动作标签泄漏给它了。

The equation summarizes the stage split; flow follows this knowledge base’s noise-to-action convention. The original model also injects flow time through adaptive RMSNorm. The attention pattern matters: expert tokens read the observation/prompt/state prefix and each other, but not FAST action answers, preventing label leakage during training.

分层推理：同一个骨干，分别预测子任务和动作Hierarchical inference: shared backbone, subtask and action predictions

比如给一句“收拾厨房”，模型先用文字预测出“拿起盘子”这样的子任务，再让连续专家根据这个子任务和最新的观测生成动作。两级共用一个 VLM 骨干，但输出头不同。文字子任务是一个看得见的中间结果，人也可以在这一层用语言插话指导；底层则负责几何和接触。这种分层并不保证上层总是选对：上层选错了目标，执行能力很强的底层也会认真地把错事做完。

Given a task such as cleaning a kitchen, the model first predicts a textual subtask and then conditions continuous actions on it and observations. The levels share a VLM backbone, not an output head. Text provides an inspectable interface and supports verbal guidance, while the lower level handles geometry and contact. Correct execution cannot compensate for an incorrectly selected subtask.

评测主要在训练时没见过的厨房和卧室里进行，按整个流程的完成进度打分。这并不能证明它能学会任意新技能，也不能把“平均完成了多少步”当成“整段任务一次做成的概率”。读 π₀.₅ 的结果时，要同时看环境是怎么划分的、允不允许语言指导、子任务覆盖了哪些，以及它和 in-domain 策略比结果如何。

Evaluation emphasizes unseen kitchens and bedrooms and includes task-progress metrics. It does not establish arbitrary new skills; average completed steps are not identical to full-task success. Inspect environment splits, allowed verbal guidance, subtask coverage and in-domain comparisons.

6Pretraining：每类数据提供了什么监督Pretraining: what each data source supervises

网络图文提供物体、语义和任务方面的先验；人类视频提供物体变化、交互和动作的先后顺序；机器人轨迹提供在具体控制接口下的 action labels；仿真则能提供奖励、特权状态和大量试错。这些数据不能按总小时数直接相加：动作能不能观测到、身体对不对得上、任务是不是重复覆盖，都会影响它们实际提供了多少监督。

Web images/text provide semantics, human video supplies interactions and temporal structure, robot trajectories ground actions, and simulation supplies privileged state, rewards and exploration. Total hours alone cannot equate these sources: action observability, body correspondence and diversity determine usable supervision.

Knowledge Insulation：监督走哪条路，梯度走哪条路Knowledge insulation: supervision and gradient paths

Knowledge Insulation（KI）[46] 处理的是另一个优化问题：随机初始化的连续专家，可能把破坏表征的梯度传回已经 Pretraining 好的骨干。它的做法是用离散动作监督来训练骨干，连续专家只读取这些表征，连续损失的梯度不回传到骨干。这样“骨干学机器人知识”和“专家学快速连续解码”就走了不同的监督路径。π₀.₅ 的两阶段训练、attention mask 和 KI 是三个不同的东西，别混为一谈。

Knowledge insulation (KI) [46] addresses optimization interference from a randomly initialized continuous expert. Discrete action supervision adapts the backbone, while the continuous expert reads its features with the continuous-loss gradient into the backbone insulated. This separates robot-knowledge adaptation from continuous decoding. Two-stage training, attention masks and gradient insulation are distinct mechanisms.

GR00T N1 的“数据金字塔”把真机、仿真和生成数据放在不同的层级；per-embodiment 投影解决了各机器人输入输出维度不同的问题，但并不能说明所有机器人共享同一种接触物理 [7]。后来的 GR00T 2 又把视频和动作的联合建模放进了主线 [50]，所以要按报告的版本去看架构的变化。

GR00T N1 mixes real, simulated and generated data. Body-specific projections accommodate dimensions without proving identical contact physics across bodies [7]. GR00T 2 later incorporates joint video-action modeling [50]; architecture claims should be attached to report versions.

7实时性、记忆与分层Real-time control, memory and hierarchy

每秒输出的动作多，不代表反应快。一个模型一次生成很多步，actions/s 可以很高，但可能隔很久才重新看一眼现场。至少应该分别报告视觉采样、端到端推理、每次执行多少步、插值和电机控制环各自的时间尺度。大模型的语义计算和快速反应可以分层处理，但缓存的语义信息也可能已经过时。

High action throughput does not imply low feedback latency. A large output chunk can inflate actions/s while delaying the next observation. Report camera sampling, end-to-end inference, execution prefix, interpolation and motor-loop timing separately. Hierarchy can decouple semantic computation from reactions, but cached semantics become stale.

RTC：模型在算，身体还在动RTC: the body moves while inference runs

Real-Time Chunking 研究的是异步推理时的衔接问题：等下一段动作算出来，上一段已经执行了一部分，必须保证新旧两段计划在接下来的执行时间上能接得上 [48]。它和 ACT 在同一时刻对多个预测做 ensemble 有关系，但不是同一个算法；和 UMI 匹配传感与执行的时延也不是一回事。

Real-time chunking handles asynchronous inference: by the time a new chunk is ready, part of the previous one has executed, so the future plans must be compatible [48]. It is related to, but distinct from, ACT temporal ensembling and UMI sensor/actuator latency matching.

记忆：不等于无限加长 observation historyMemory is more than a longer observation history

短期历史用来估计速度，或者在遮挡时推测局部状态；长期记忆记的是“哪个柜子已经翻过了”“用户刚才把目标改成了什么”。PI 的 MEM 等工作把这两种时间尺度分开处理 [47]。检验记忆能力，要用必须依赖过去信息才能完成的任务，并和只看当前画面的基线比较；context window 更大，并不能直接当成记忆能力的证据。

Short history supports velocity and local hidden-state estimation; long memory tracks searched locations and changed instructions. Work such as PI MEM separates these time scales [47]. Evaluate tasks that require past information against current-frame baselines rather than using context-window size as a memory metric.

Gemini Robotics-ER 这类推理模块和动作模型的分工也不一样：推理给出的计划、空间关系或工具调用，要经过能执行的接口才能验证。整个系统做成了一件事，不代表每一步都是同一个网络直接控制的 [51]。

Reasoning modules such as Gemini Robotics-ER differ from action models: plans, spatial relationships and tool calls still need executable validation. System-level success does not imply direct control by one network at every layer [51].

π*0.6 / RECAP 把部署中的成功、失败和人工纠正都用来估计价值、改进策略 [11]；RLT 关注的是如何更高效地在线优化精细操作 [49]。这两个工作不能当成“又一个 π checkpoint”来看，真正的区别在于反馈从哪来、优化的是什么，以及部署时策略的接口。

π*0.6/RECAP connects deployment outcomes and corrections to values and policy improvement [11]; RLT studies efficient online improvement for precise manipulation [49]. Feedback source, optimization target and deployed interface matter more than viewing these as another checkpoint name.

π*₀.₆ / RECAP：从行为数据里估计优势π*₀.₆ / RECAP: estimate advantages from behavioral data

RECAP 把问题拆成三步：收集数据、学价值、提取策略。Value model 从任务结果学习每个状态的价值，用动作前后的进展来估计优势，再把“优势高不高”作为策略的条件输入。训练时好行为和坏行为都保留，部署时只要求输出优势高的行为。这既不同于只挑成功示范来训练，也不同于直接对整个 VLA 跑 PPO。

RECAP separates collection, value learning and policy extraction. A value model learns from task outcomes, advantages characterize behavioral progress, and an advantage indicator conditions policy training. Both favorable and unfavorable behavior remain informative; deployment requests favorable behavior. This differs from successful-demo filtering or direct PPO on the entire VLA.

π*₀.₆ [11] 先用 Pretraining 数据得到初始模型，再结合自主尝试、失败和专家介入反复改进。它最依赖的是结果标注和 critic 准不准：如果价值函数把被遮挡的画面或某个中间状态误判成“有进展”，策略也会跟着学偏。报告吞吐量提升时，还应分清是动作变快了、恢复能力变强了，还是成功率提高了，这三者要分开报告。

π*₀.₆ [11] starts from pretrained data, then incorporates autonomous attempts, failures and expert interventions. Outcome labeling and value accuracy are critical: mistaken progress estimates can shape policy improvement. Throughput gains should be separated into faster actions, better recovery and increased completion reliability.

Generalist 说的“不改权重就能适应”和 Sunday 的“一次示范 SFT”，需要用不同的实验来检验 [20, 43]。说一个模型“学会了新技能”时，要讲清楚是加了 context、更新了权重、重新采了在线数据，还是只是换了任务提示。

Fixed-weight adaptation claims from Generalist and one-demonstration SFT from Sunday answer different questions [20, 43]. “Learning a skill” must specify whether it adds context, updates weights, collects online data or only changes a prompt.

9π₀.₇ 及相关工作：可引导、记忆与在线适配π₀.₇ and related methods: steering, memory and online adaptation

π₀.₇ [16] 把“任务条件”扩展成了多种可以用来引导模型的信息：语言指令、行为质量或速度这类元信息、控制模式，以及视觉子目标。来源和质量各不相同的数据，靠这些条件区分开；部署时，再通过条件挑选想要的行为。它沿用了“给条件、出连续动作”的路线，但把上层的接口开放给了人或规划系统。

π₀.₇ [16] broadens policy conditioning to language, behavior-quality or speed metadata, control modes and visual subgoals. Conditions distinguish heterogeneous behavior during training and specify desired behavior at deployment, exposing a richer interface to people or planners.

这些是围绕 VLA 的几条不同研究线，不是一个接一个替换的 checkpoint。π₀.₇ 的新任务演示也要拆开看：用到的基础技能以前见没见过，有没有人一步步提示，视觉子目标是谁给的。MEM 的历史信息和 RTC 的时序衔接解决的是另外两个瓶颈；加提示既不能代替记忆，也不能降低推理延迟。

These are distinct VLA research directions rather than a single sequence of replacement checkpoints. For π₀.₇’s novel-task examples, separate familiar component skills, stepwise coaching and the source of visual subgoals. Memory and execution timing address different bottlenecks.

10跨本体与人形：共享什么，适配什么Cross-body and humanoid control: share or adapt?

把不同机器人的动作归一化到同一个 tensor 里，embodiment gap 并不会因此消失。同样的末端位移，不同机器人可能需要完全不同的关节运动；夹爪和灵巧手的接触方式也不同；humanoid 还要顾及支撑和平衡。共享表征、body-specific adapters、relative EE actions 和底层 controller，是在不同层面上解决这个问题的办法。

Normalizing actions into one tensor does not remove embodiment gaps. Identical end-effector motion may require different joints; grippers and dexterous hands have different contact semantics; humanoids also require support and balance. Shared representations, body-specific adapters, relative EE actions and low-level controllers address different layers.
