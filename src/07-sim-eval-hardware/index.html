1基础设施怎样改变学习问题How infrastructure changes the learning problem

机器人学习的结果由算法和基础设施共同决定：simulator 定义能探索什么，硬件定义能执行什么，benchmark 定义最后如何比较。一个模型换了相机、控制器或 reset 流程，即使网络参数相同，也可能面对不同的决策问题。

Robot-learning results depend on infrastructure as well as algorithms. Simulators define exploration, hardware defines executable behavior and benchmarks define comparison. Changing cameras, controllers or resets can change the decision problem even with identical network weights.

这里把工具选择放在问题之后：是要学高速 locomotion、精细装配、柔性物体操作，还是评估 VLA 的语义泛化？不同任务需要不同的接触精度、渲染质量和数据吞吐，不能只按一个 simulator 的宣传 FPS 选择。

Choose tools after defining the problem: fast locomotion, precision assembly, deformable manipulation or semantic generalization require different contact fidelity, rendering and throughput. A headline simulator FPS does not determine suitability.

Isaac Lab 是学习框架，MuJoCo 与 Newton 属于物理引擎；benchmark 又是它们上面的任务与评测协议。这些层可以组合，不应当作同层的排行榜。工具演进很快，复现实验应固定版本、backend、步长、control decimation 与 solver 设置。

Isaac Lab is a learning framework; MuJoCo and Newton are physics engines; benchmarks specify tasks and protocols above them. These layers can be combined. Reproduction requires pinned versions, backends, timesteps, control decimation and solver settings.

吞吐量需要完整口径：无渲染状态环境的 transitions/s，与包含 RGB、policy inference、日志和 reset 的端到端吞吐不是同一个数字。训练能跑得快，也不保证接触更正确；跨引擎测试可暴露对某个数值模型的过拟合。

State-only transitions/s is different from throughput including RGB rendering, policy inference, logging and resets. Speed does not imply contact fidelity. Cross-engine tests can expose overfitting to one numerical model.

Domain randomization 将参数分布变宽，代价可能是策略更保守或训练更难；系统辨识缩小参数误差，但只覆盖选定模型；ASAP 用真实反馈学习仿真中的动作修正，再在对齐环境微调策略 [67]。这些方法处理的误差不同，不能把“用了随机化”当作通用的迁移证明。

Randomization widens coverage but can make training harder or behavior conservative. Identification reduces error within a chosen model. ASAP learns simulation-side action correction from real feedback before policy fine-tuning [67]. These address different mismatches; randomization alone is not evidence of successful transfer.

评估 gap 时，应把 embodiment、execution 与 visual 分开。UMI 的相对末端接口减少身体映射问题，依然要处理目标机器人可达性和时延；同理，一个形状完全一致的仿真机器人仍可能有很大的执行误差 [3]。

Separate embodiment, execution and visual gaps. UMI’s relative EE interface reduces correspondence problems while retaining feasibility and latency requirements. A geometrically identical simulated robot can still have a large execution gap [3].

4Real2Sim 与生成式仿真Real-to-sim and generative simulation

Real2Sim 从真实图像、视频或扫描重建训练环境。视觉重建、物理资产和训练任务是三种不同产物：一个 Gaussian Splat 能渲染得像现场，不意味着它自动包含碰撞网格、关节、质量、摩擦或可用 reward。可执行模拟器需要把这些信息接起来。

Real-to-sim builds training environments from images, video or scans. Visual reconstruction, physical assets and learning tasks are different products: photorealistic Gaussian splats do not automatically provide collision meshes, joints, mass, friction or rewards. Executable simulation needs these interfaces.

SGS：已有模拟器里，如何访问有用的状态SGS: reach useful states inside an existing simulator

SGS 的重点是 exploration bottleneck：在大规模仿真 RL 中组织训练状态与课程，让策略得到更有用的学习经验 [55]。它属于仿真训练机制，不能因为放在 Real2Sim 章节附近就把它称为场景重建方法。RGB student 的部署效果还要与 privileged-state expert 的仿真成绩分开看。

SGS targets the exploration bottleneck by organizing training states and curricula in large-scale simulation RL [55]. It changes training, not scene reconstruction. Deployment results for an RGB student must be distinguished from simulated privileged-state expert scores.

SGS 详解与原始 threadSGS method and original thread →

生成更多场景能增加外观与布局覆盖；生成更好的 reset、课程和奖励能改变探索难度。这是两条独立轴。前者多而后者无效时，机器人可能在一百万个漂亮场景里重复失败。

More scenes expand appearance and layout coverage; better resets, curricula and rewards change exploration difficulty. These are separate axes. Scene diversity alone can still produce repeated failure across a large collection of attractive environments.

HumanoidBench 的价值之一是把高维身体与双手暴露给统一任务，揭示“从零 flat RL”与“已有低层技能的分层系统”面对的难度不同。比较算法时，是否用参考动作、预训练模型、特权观测或额外数据，应该与算法名一起报告。

HumanoidBench exposes whole-body and dexterous action dimensions in common tasks, clarifying the distinction between flat RL from scratch and systems with pretrained low-level skills. Report references, pretraining, privileged observations and extra data alongside algorithm names.

RoboArena 用成对比较降低跨机构任务差异带来的部分噪声，但排名不是脱离分布的绝对能力刻度。应同时查看比较图是否连通、每对策略覆盖多少任务、评估者偏好与不确定性。一个总分不应遮住某类重要任务上的失败。

RoboArena’s pairwise protocol reduces some cross-site confounding, but rankings remain distribution-dependent. Inspect comparison coverage, connectivity, evaluator preferences and uncertainty. An aggregate rank should not hide failures on an important task family.

6真机评测：成功率需要一个完整分母Real evaluation needs a complete denominator

先定义一次试验：初始状态如何采样、时间上限、是否允许重试、什么时候算成功、谁判断、人工介入如何计入。然后再报告 k/n。剪辑视频展示能力存在，重复且预先定义的试验才能测量能力的可靠性。

Define a trial before reporting k/n: initial-state sampling, time limits, retries, success criteria, adjudication and interventions. A clip demonstrates an occurrence; repeated trials under a specified protocol measure reliability.

完整任务成功率Full-task success成功试验数 / 全部预先定义试验；附不确定区间和每任务分布Successful trials / all predefined trials, with uncertainty and per-task results
人工介入率Intervention rate需要接管或复位的试验比例，以及每小时次数Fraction requiring takeover/reset and events per operating hour
执行与恢复时间Execution and recovery time不仅计算成功片段，还记录失败、恢复和等待Include failures, recovery and waiting, not only successful clips
持续有效吞吐Sustained useful throughput完整成功任务数 / 含 reset、维护的总时间Completed useful tasks / total time including resets and maintenance
分布外表现Out-of-distribution performance分别留出物体、场景、操作者、本体和任务Separate object, scene, operator, body and task holdouts

示例：95/100 次成功的观测比例是 95%，按独立 Bernoulli 试验的 Wilson 95% 区间约为 88.8%–97.8%。这不是“真实成功率恰好 95%”，也不能覆盖未测试家庭或任务的分布偏差。连续在同一设置下反复尝试还可能相关，单纯增加次数不等于增加独立证据。

For illustration, 95/100 successes gives an observed rate of 95%, with an approximate 88.8%–97.8% Wilson 95% interval under independent Bernoulli trials. This does not establish exactly 95% reliability or cover distribution shift to untested homes. Repeated trials under one setup may also be correlated.

层次Layer会改变学习的具体量Learning-relevant quantities

例如更柔顺的夹指让抓取容错增大，可能比增加网络容量更有效；更高分辨率相机若带来额外延迟，又可能降低动态任务表现。硬件改动之后应重新确认动作标签和 observation 时间，避免模型学习到系统同步错误。

More compliant fingers can increase grasp tolerance more effectively than a larger model. A higher-resolution camera may add latency and hurt dynamic tasks. After hardware changes, recheck action labels and observation timing to avoid learning synchronization artifacts.

记录 target 与 actual state 可以观察 tracking error；记录 command、capture、arrival 和 execution 时间有助于定位延迟。没有这些日志，失败可能被错归因成“模型不理解”，实际却是命令没有按预期执行。

Logging targets and achieved states exposes tracking error; capture, arrival, command and execution timestamps expose delay. Without these records, execution faults can be misdiagnosed as failures of model understanding.

8从研究结果到可复现系统From research result to reproducible system

最低限度的实验记录应同时包含：模型与数据版本、机器人和传感器配置、动作与 observation 定义、控制频率和时延、训练预算、任务 split、完整分母与失败分类。这些不是附属细节，而是理解性能来自哪里所需的条件。

A useful experimental record includes model/data versions, hardware and sensors, action/observation definitions, control timing, training budget, task splits, trial denominators and failure categories. These define what the result means.
