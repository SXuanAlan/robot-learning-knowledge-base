Google DeepMind

Gemini Robotics 的关键，是把 Embodied Reasoning、动作策略和本地部署拆成几个互相配合的组件，而不是让一个语言模型包揽所有时间尺度上的控制。

Gemini Robotics separates embodied reasoning, action policies and local deployment into cooperating components, rather than using one language model at every control timescale.

分清这三个角色，直接影响怎样读论文：空间推理测得好，不等于机器人任务的成功率高；工具调对了，也不等于接触操作做成了。整个系统能做到多好，取决于这些组件之间能不能传递足够的信息，以及执行偏离计划时能不能及时修正。

Spatial-reasoning scores are not robot task-success rates, and correct tool calls do not establish correct contact execution. The system depends on sufficient information crossing component boundaries and correction when execution diverges from the plan.

21.5：把 Agent 接到动作策略上1.5: connecting agents to action policies

Gemini Robotics 1.5 的报告把 Embodied Reasoning 和动作模型结合起来，研究任务分解、先思考再行动，以及跨本体迁移 [51]。这样上层可以借助外部信息来组织工作，动作模型负责落实到具体的机器人上。在 Agentic Robotics 的分类里，它属于“编排 Learned Policy”这一类。

Gemini Robotics 1.5 combines embodied reasoning and action models, studying task decomposition, reasoning before acting and transfer across embodiments [51]. High-level reasoning organizes work while the policy grounds it in a robot: an instance of orchestrating learned policies.

模块化的好处是推理和动作可以分开改进，但模块之间的接口可能丢掉细节。比如“把物体放进去”这句话，没说要避开哪个障碍，也没说夹爪里的东西是不是已经滑了。好的 Agent 接口应该能返回执行的状态和失败的类型，而不只是“完成”或“没完成”。

Modularity permits independent progress in reasoning and action, but interfaces can lose information. A placement request may omit an obstacle or a slipping grasp. Useful agent interfaces should return execution state and failure type, beyond a binary completion flag.

3Robotics 2：从桌面走向全身控制和多机协作Robotics 2: whole bodies and collaboration

Robotics 2 展示了用同一个 checkpoint 控制不同的手和不同的机器人，并扩展到了 Apollo 2 的全身动作；ER 2 负责理解任务进度、协调多台机器人 [17]。所以一条长任务同时考验动作能力、状态记忆和调度能力，只看最后有没有完成，判断不出哪一项最强。

Robotics 2 shows a shared checkpoint across bodies and hand configurations, with Apollo 2 whole-body motion; ER 2 handles progress understanding and multi-robot coordination [17]. Long tasks combine action, memory and scheduling, so completion alone does not isolate the strongest component.

多台机器人协作，尤其需要把责任分清楚：哪台机器人占着工作空间，哪台已经交接完了，物体的状态由谁来确认？这些问题很像分布式系统里的共享状态和冲突处理，也说明了为什么语言能力再强，也需要一套明确的执行协议。

Collaboration needs explicit ownership: which robot occupies a workspace, which completed a handoff, and who confirms object state? Shared-state and conflict-resolution problems explain why stronger language models still need execution protocols.

4On-Device：模型适配与推理延迟On-device models: adaptation and inference latency

On-Device 2 面向本地运行。官方给出的设置是：接入一台新的双臂机器人，用不到约两百个示例、几个小时就能完成适配 [17]。这是适配新本体的成本，并不是说每个任务都只要这么点数据。接入新硬件、学新任务、在部署现场做校准，这几项应该分开记录。

On-Device 2 targets local execution; the release describes adaptation to new bimanual bodies with typically fewer than 200 examples in a few hours [17]. That is an embodiment-adaptation setting, not the total training requirement for every task. Separate hardware adaptation, skill learning and site calibration.

和云端的大模型相比，本地运行的策略省掉了网络等待；但最终表现仍然受观测频率、动作块长度和与上层往返时间的影响。和 PI 的 RTC 对照着看，能看到两种互补的思路：一是降低每次预测的成本，二是让预测和执行同时进行。

Local policies reduce network waits, while observation rate, chunk length and high-level round trips still matter. Compare PI’s RTC: lowering prediction cost and overlapping prediction with execution are complementary.

5从报告到系统评测From reports to system evaluation

Robotics 2 的安全报告加入了对 Agentic 编排和不确定性处理的评测 [57]。技术上值得关注的是：系统能不能识别出不该执行的工具调用，知不知道什么时候该求助，这些判断最后有没有真的拦住动作。推理层通过了测试，不代表底层的轨迹就一定安全。

The Robotics 2 safety report evaluates agentic orchestration and uncertainty handling [57]. Examine whether unsafe calls are detected, uncertainty prompts help, and those decisions actually stop execution. Reasoning-level tests do not establish low-level trajectory safety.

可以和 Dyna 比工作流记忆，和 Figure 比全身执行，和 PI 比语义骨干与动作策略怎样连接。如果各家能用一套共同的评测协议，最有价值的是同时报告任务完成情况、人工介入、耗时和出错后的恢复。

Compare workflow memory with Dyna, whole-body execution with Figure, and semantic–action connections with PI. A shared evaluation should track completion, human intervention, elapsed time and recovery.
