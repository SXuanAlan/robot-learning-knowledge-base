Figure

Figure 的路线没法用“Helix”一个词概括。初代 Helix 研究的是从语义到动作的双系统；Helix 02 加上了全身执行层；Helix 2.5 则换了 Pretraining 的起点，并把在没去过的家庭里的测试放到了最显眼的位置。

Figure’s route changes across releases: Helix couples semantics and actions, Helix 02 adds whole-body execution, and Helix 2.5 changes the pretraining foundation while testing unseen homes.

这三次发布说明，“语义能力要不要复用”和“物理动作该怎样 Pretraining”，都是可以改变的设计选择。同一家公司，技术路线也可能从 VLA 转到物理经验 Pretraining 这一边。

This evolution makes reuse of semantics and pretraining of physical behavior separate design choices. A company can change those choices across releases.

2Helix 02：全身控制的接口Helix 02: whole-body interfaces

Helix 02 公开的分工是：S2 负责目标和语义，S1 以 200 Hz 给出全身的关节目标，S0 以 1 kHz 执行，负责平衡和接触。S0 是用人体运动作为目标、在仿真里用 RL 训练的 [13]。并不是让一个很慢的语言模型每毫秒去输出力矩。

Helix 02 describes S2 for semantics, S1 for whole-body targets at 200 Hz, and S0 for execution at 1 kHz. S0 learns from human motion targets and simulated RL [13]. The architecture separates deliberation from fast balance and contact control.

分层的好处是上层只管指定动作，下层负责持续稳定地执行；代价是上层必须知道下层能做到什么。如果目标够得着，底层却一时跟不稳，视觉策略就得看出偏差、重新选择动作。所以看各层的频率时，也要同时看反馈是怎样闭环的。

Hierarchy lets a policy request motion while a controller maintains stability. It also requires the policy to account for controller capabilities. A geometrically reachable target may be dynamically unstable; feedback must allow the policy to react to tracking errors. Frequencies alone do not describe that loop.

3Helix 2.5：换了 Pretraining 的起点Helix 2.5: a different starting point

Helix 2.5 从随机初始化开始，用 Index 数据做 Pretraining；报告专门把它和 Helix 02 以 VLM 为起点的做法区分开 [40]。这样一来，它和 Generalist 的物理经验路线面对的是同一个问题：什么样的数据和训练目标，才能学出既能迁移、又好控制的表征？

Helix 2.5 starts from random initialization and pretrains on Index, explicitly differing from Helix 02’s VLM foundation [40]. That creates a comparison with Generalist: which data and objectives produce transferable, controllable representations?

从头训练效果好，并不能证明网络上的知识没用。要比较，就得在相同预算下分别比较模型初始化、数据配比和输出接口；如果三者一起变了，最后的差异只能归功于整套系统。读公开报告时，要把作者已经验证过的改动和还没公开的架构细节分开看。

Training from scratch does not by itself show that web pretraining lacks value. Initialization, mixtures and action interfaces need matched-budget comparisons. If all change together, results compare systems rather than isolate one architectural cause.

官方报告用固定的模型，在三十个没去过的家庭里测试了这些完整的家务 [40]。这组分母既说明了泛化上的进步，也说明还有不少失败：一共有 183 次没完成。在新环境里 zero-shot，不代表这些技能本身没做过 Post-training；还需要知道每项家务怎样才算完成，以及几项任务的难度是否相差很大。

The report tests these behaviors with a fixed model across thirty unseen homes [40]. The denominators show both transfer and 183 unsuccessful trials. Zero-shot deployment in a home does not imply no prior task training; the definition and difficulty of each behavior matter.

Tony Zhao 针对这组结果强调了可靠性 [41]。这引出一个很实际的问题：家用机器人的人工介入要少到什么程度，才真正有用？但这并不能说明另一家公司就更好，因为 Sunday 的单件叠衣评测用的是另一种“成功”的单位。

Tony Zhao’s response emphasizes reliability [41], raising the useful question of how infrequently a home robot may need help. It does not establish another company’s superiority: Sunday’s garment-folding evaluation uses a different success unit.

5和 Dyna、Reward 在结构上的联系Connections with Dyna and Reward

Figure、Dyna 和 Reward 都把高速执行交给了专门的控制层，但接口各不相同：全身关节目标、URR 任务空间轨迹和通用的手部动作，不能直接画等号。接口越接近人的表达方式，数据越容易共用；越接近执行器，越能表达这台机器人自己的细节。在这两头之间怎么分配职责，是比“端到端还是分层”更具体的比较角度。

Figure, Dyna and Reward all use dedicated execution layers, but joint targets, URR trajectories and shared hand actions are different interfaces. Human-like interfaces ease sharing; actuator-level ones express body-specific detail. Allocation between them is a more useful comparison than architecture slogans.
