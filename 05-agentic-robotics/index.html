Agentic Robotics：语言模型控制机器人的四种接口（2022–2026）Agentic Robotics: Four Interfaces for Controlling Robots with Language Models (2022–2026)

摘要Abstract

本文梳理 Agentic Robotics 方向：用没有在机器人数据上训练过的通用语言模型（LLM 或 VLM）控制机器人。我们按语言模型的输出进入机器人控制栈的位置，把相关工作分为四类：Skill Selection、Program Synthesis、Policy Supervision 和 Direct Control。2022–2023 年的工作集中在前两类，语言模型负责规划或编写代码，执行依赖预先构建的技能、Perception API 和 Motion Planner；2024–2025 年，随着 VLA 等 Learned Policy 成熟，语言模型更多承担编排角色；2025–2026 年，前沿通用模型开始在“编写整套机器人软件”和“逐步输出动作”两端被直接评测。现有证据表明，同一模型在不同接口下的表现差异很大；高层规划进步最快，而精细的闭环控制仍是主要瓶颈。我们还用 System 2/1/0 三层架构分析了 System 2 变强后下两层的演变，辩证地讨论了 Direct Control 的速度瓶颈，并介绍了让 System 2 离开控制回路、为下层构建仿真与数据的 Agentic Real2Sim。文中多数定量结果来自原作者或公司自报，测试条件不同，不宜直接比较。

This page surveys agentic robotics: controlling robots with general-purpose language models (LLMs or VLMs) that were not trained on robot data. We group the work by where the language model's output enters the robot's control stack: skill selection, program synthesis, policy supervision and direct control. Work in 2022–2023 concentrated on the first two, with the language model planning or writing code while execution relied on prebuilt skills, perception APIs and motion planners. In 2024–2025, as learned policies such as VLAs matured, language models increasingly took an orchestrating role. In 2025–2026, frontier general-purpose models began to be evaluated directly at both ends: writing a robot's entire software stack and emitting actions step by step. The evidence so far shows that the same model performs very differently across interfaces, and that high-level planning is improving fastest while fine closed-loop control remains the main bottleneck. We also use the System 2/1/0 architecture to analyze how the lower layers change as System 2 grows stronger, examine the latency bottleneck of direct control dialectically, and review Agentic Real2Sim, which moves System 2 out of the control loop to build simulations and data for the layers below. Most quantitative results here are self-reported by authors or companies under different conditions and should not be compared directly.

1用通用语言模型控制机器人：动机与范围Controlling robots with general-purpose language models: motivation and scope

机器人学习的主流路线是在机器人数据上训练专门的策略：从模仿学习、RL，到近年在大规模 Teleop 数据上训练的 VLA。Agentic Robotics 走的是另一条路：直接使用为语言、代码和网页任务训练的通用模型，通过提示、工具调用和代码把它接到机器人上。这条路线的吸引力在于，这些模型已经具备常识、推理、编程和使用工具的能力，而且不需要为每台机器人重新收集数据。

The mainstream of robot learning trains specialized policies on robot data, from imitation and reinforcement learning to the recent VLAs trained on large teleoperation datasets. Agentic robotics takes another route: it connects general-purpose models trained for language, code and web tasks to a robot through prompts, tool calls and code. The appeal is that these models already bring common sense, reasoning, programming and tool use, and they do not need new data for every robot.

这一思路并不新。2022 年的 SayCan [1] 和 Code as Policies [4] 已经让语言模型规划任务、编写控制程序。但长期以来的共识是：语言模型适合做高层规划，不适合 Direct Control，理由包括推理延迟高、空间理解不足和物理常识欠缺（Isola [24] 对这些质疑有简要总结）。2026 年的几项工作开始挑战这一共识。在 Anthropic 的 Project Fetch 第二期 [16] 中，Claude Opus 4.7 几乎独立完成了一台四足机器人从连接、感知到控制的全部编程；NVIDIA 的 Astranomy [29] 和第三方机构 Robocurve [21, 22] 把 GPT-6 Astra 和 Claude Fable 5/5.1 直接当作机械臂策略来评测；Claude Fable 5.2 的发布报告 [32] 给出了 RoboDojo 仿真双臂基准上的成绩和真机演示（图 1）。

The idea is not new. In 2022, SayCan [1] and Code as Policies [4] already had language models plan tasks and write control programs. But the long-standing consensus was that language models suit high-level planning rather than direct control, because of high inference latency, weak spatial understanding and limited physical common sense (Isola [24] summarizes these objections). Several 2026 results began to challenge that consensus. In phase two of Anthropic's Project Fetch [16], Claude Opus 4.7 programmed a quadruped robot almost entirely on its own, from connecting to it through perception and control. NVIDIA's Astranomy [29] and the third-party lab Robocurve [21, 22] evaluated GPT-6 Astra and Claude Fable 5/5.1 directly as arm policies. The Claude Fable 5.2 launch report [32] gives scores on the RoboDojo simulated two-arm benchmark and shows real-robot demonstrations (Figure 1).

2按控制接口的分类A taxonomy by control interface

对这一方向，最有用的分类依据是：语言模型的输出在哪一层进入机器人的控制栈（图 2）。从高到低有四种位置。

The most useful way to classify this work is by the layer of the robot's control stack at which the language model's output enters (Figure 2). From top to bottom there are four positions.

  • Skill SelectionSkill selection输出进入任务层Enters at the task level
    模型从预先训练好的 Skill Library 中选出下一步执行的技能，或从“前进、旋转、拍照”这类高层动作中选择。The model picks the next skill from a library of pretrained skills, or from high-level actions such as “move forward”, “rotate” and “take a picture”. 代表工作：Examples: SayCan [1] · Inner Monologue [2] · ProgPrompt [3] · Butter-Bench [12]
  • Program SynthesisProgram synthesis输出进入程序层Enters at the program level
    模型编写控制程序、3D Value Map 或 reward 函数，交给 Perception API、Motion Planner 或 RL 执行。The model writes control programs, 3D value maps or reward functions, which perception APIs, motion planners or reinforcement learning then execute. 代表工作：Examples: Code as Policies [4] · VoxPoser [5] · Eureka [6] · Project Fetch [14, 16] · Waddle [23]
  • Policy SupervisionPolicy supervision输出进入策略层Enters at the policy level
    模型向预训练的 Learned Policy（通常是 VLA）下达语言指令，或审核它提出的动作。The model gives language commands to a pretrained learned policy, usually a VLA, or reviews the actions it proposes. 代表工作：Examples: AutoRT [7] · Helix [8] · Hi Robot [9] · Gemini Robotics 1.5 [11]
  • Direct ControlDirect control输出进入动作层Enters at the action level
    模型在每一步输出末端目标、关节力矩或动作，下层只剩底层控制器。The model outputs end-effector targets, joint torques or actions at every step, leaving only a low-level controller below it. 代表工作：Examples: Claude plays robotics [17] · Robocurve [21, 22] · Astranomy [29]

这四种位置之间存在明确的取舍。接口越靠上，模型处理的问题越抽象，但系统能做什么受限于下层已有的能力：Skill Library 里没有的技能无法被选中，Perception API 识别不了的物体无法写进程序，VLA 做不到的动作也不会因为监督而出现。接口越靠下，系统越不依赖预先构建的模块，但模型必须自己完成闭环控制，也就是每一步都根据新的观测修正动作；而一次推理往往需要数秒到数十秒（Astranomy 直接模式平均每次调用约 18.6 秒 [29]），这对需要快速反馈的接触操作十分不利。

These positions involve a clear trade-off. The higher the interface, the more abstract the problem the model handles, but what the system can do is limited by the layers below: a skill missing from the library cannot be selected, an object the perception API cannot recognize cannot be written into a program, and an action the VLA cannot perform will not appear through supervision. The lower the interface, the less the system depends on prebuilt modules, but the model must close the control loop itself, correcting its actions from each new observation, while a single inference often takes seconds to tens of seconds (about 18.6 s per call in Astranomy's direct mode [29]). That is a serious handicap for contact-rich manipulation, which needs fast feedback.

[17] 的结果直观地体现了这一取舍：在机械臂操作任务上，模型直接驱动关节时完整完成任务的比例只有 0–5.5%；改为监督一个预训练的 VLA 后，表现大幅提高；而对人形机器人，目前的模型只有借助预训练策略才能控制。Astranomy [29] 在同一基准上比较了 GPT-6 Astra 的三种用法：直接输出末端动作（66.3%）、审核 World Action Model 给出的 Action Chunk（66.5%），以及在 Codex 中以 agent 会话运行、可以编写代码并调用工具（74.8%）。最后一种效果最好，但每回合成本约为直接模式的 18 倍。

Results in [17] make the trade-off concrete. On arm manipulation, models driving the joints directly completed the full task only 0–5.5% of the time; supervising a pretrained VLA instead raised performance substantially; and current models could control a humanoid only through a pretrained policy. Astranomy [29] compared three ways of using GPT-6 Astra on one benchmark: emitting end-effector actions directly (66.3%), reviewing action chunks proposed by a world action model (66.5%), and running as an agent session in Codex that can write code and call tools (74.8%). The last worked best but cost about 18 times as much per episode as the direct mode.

3语言模型作为任务规划器Language models as task planners

SayCan [1] 是这一类工作的起点。它把规划拆成两个分数：语言模型评估某个技能对完成指令“是否有用”，每个技能自带的 Value Function 评估它在当前状态下“能否成功”，两者相乘选出下一步。这样，语言模型的常识被约束在机器人实际能做的范围内。在真实办公室厨房的 101 条指令上，PaLM-SayCan 的规划成功率为 84%，执行成功率为 74%。

SayCan [1] is the starting point for this class. It splits planning into two scores: the language model estimates whether a skill is useful for the instruction, and each skill's value function estimates whether it can succeed in the current state; the product of the two picks the next step. This keeps the language model's common sense within what the robot can actually do. On 101 instructions in a real office kitchen, PaLM-SayCan planned correctly 84% of the time and executed successfully 74% of the time.

SayCan 的规划是开环的：某个技能执行失败后，规划器并不知道。Inner Monologue [2] 把成功检测、场景描述和人的反馈以文本形式写回提示，让语言模型可以根据执行结果重新规划，并在仿真桌面、真实桌面和真实厨房三种场景中验证了这种闭环。ProgPrompt [3] 改变的是提示的形式：用 Python 风格的程序列出可用动作和场景中的物体，并给出示例程序，让模型生成带断言检查的任务程序；它在 VirtualHome 家务任务和真实机械臂上做了验证。

SayCan plans open-loop: when a skill fails, the planner does not know. Inner Monologue [2] writes success detection, scene descriptions and human feedback back into the prompt as text, letting the language model replan from execution results, and demonstrated this closed loop in simulated tabletop, real tabletop and real kitchen settings. ProgPrompt [3] changes the form of the prompt instead: it lists available actions and scene objects as Python-style programs with example programs, and the model generates task programs with assertion checks; it was validated on VirtualHome household tasks and a real arm.

这类方法的上限由 Skill Library 决定：语言模型只负责“选”，不负责“做”，新任务需要新技能。2025 年的 Butter-Bench [12] 用这种接口重新测量了前沿模型的编排能力：模型控制一台扫地机器人形态的移动机器人，只能调用“前进、旋转、导航到坐标、拍照”等高层动作，在办公室里完成“把黄油递过来”的任务。表现最好的 Gemini 2.5 Pro 完成率为 40%，Claude Opus 4.1 为 37%，人类平均为 95%；失败主要来自空间推理，例如原地反复旋转直至迷失方向。第 7 节会再讨论这一基准的设计。

The ceiling of this approach is set by the skill library: the language model only chooses and does not act, so new tasks require new skills. In 2025, Butter-Bench [12] used this interface to measure the orchestration ability of frontier models again. The model controls a mobile robot with the form factor of a robot vacuum and can only call high-level actions such as move forward, rotate, navigate to a coordinate and take a picture, with the task of passing the butter in an office. The best model, Gemini 2.5 Pro, completed 40% and Claude Opus 4.1 37%, against 95% for humans; failures came mostly from spatial reasoning, such as rotating in place until disoriented. Section 7 returns to the benchmark's design.

4以代码表示策略Policies as code

与技能列表相比，代码的表达能力强得多：可以有循环和条件判断，可以做数值计算，还可以调用感知和控制接口。Code as Policies [4] 让语言模型直接生成 Python 策略代码；遇到尚未定义的函数时，再递归地生成这个函数，从而组合出更复杂的行为。同一方法被用在桌面机械臂、白板绘画和移动机器人上。

Code is far more expressive than a list of skills: it allows loops and conditionals, arithmetic, and calls to perception and control APIs. Code as Policies [4] has the language model write Python policy code directly; when the code calls a function that does not exist yet, the model generates that function recursively, composing more complex behavior. The same method was applied to tabletop arms, whiteboard drawing and a mobile robot.

随后的工作把代码当作构造其他中间表示的手段。VoxPoser [5] 让语言模型编写代码调用 VLM，在 3D 体素空间中组合出“该去哪里”和“该避开哪里”的 Value Map，再由 Motion Planner 沿 Value Map 生成轨迹，整个过程不需要训练。Eureka [6] 把同样的思路用在 reward 设计上：语言模型编写 reward 函数代码，用 RL 训练，再根据训练结果反思并修改，形成类似进化搜索的迭代。在 29 个环境、10 种机器人上，它在 83% 的任务中超过了人类专家编写的 reward，并让仿真中的 Shadow Hand 学会了快速转笔。

Later work used code to build other intermediate representations. VoxPoser [5] has the language model write code that queries a vision-language model to compose 3D value maps in voxel space, marking where to go and what to avoid; a motion planner then generates trajectories along the maps, without any training. Eureka [6] applies the same idea to reward design: the language model writes reward-function code, reinforcement learning trains a policy with it, and the model reflects on the results and revises, iterating like an evolutionary search. Across 29 environments and 10 robots it beat expert-written rewards on 83% of tasks, and it taught a simulated Shadow Hand fast pen spinning.

2025–2026 年，Program Synthesis 的规模发生了变化：模型不再只写一段策略函数，而是编写一台机器人的整套软件。Anthropic 的 Project Fetch 第一期 [14] 让 8 名没有机器人经验的员工分成两组，为 Unitree Go2 四足机器人编程，目标是让它自主捡回沙滩球，其中只有一组可以使用 Claude（Opus 4.1）。使用 Claude 的一组完成了 8 项任务中的 7 项（另一组 6 项），在两组都完成的任务上用时约为一半。第二期 [16] 把同样的任务交给 Claude Opus 4.7，在 Claude Code 中独立完成，研究员只负责连接电脑、输入初始提示和批准命令。四项任务共用时 9 分 35 秒，而不使用 Claude 的人类组用了 361 分钟；模型编写了 1,045 行代码，使用 Claude 的人类组则写了 10,309 行。但模型没能完成最后一步：把球精确地推回起点。这一步需要根据球的实时位置不断修正推动方式，正是闭环控制。

In 2025–2026 the scale of program synthesis changed: models began writing a robot's entire software stack rather than a single policy function. In phase one of Anthropic's Project Fetch [14], eight staff with no robotics experience were split into two teams to program a Unitree Go2 quadruped to fetch a beach ball on its own, and only one team could use Claude (Opus 4.1). The team with Claude finished 7 of 8 tasks (the other team 6) and took about half the time on tasks both teams finished. Phase two [16] gave the same tasks to Claude Opus 4.7 working alone in Claude Code, with a researcher only connecting the laptop, typing the first prompt and approving commands. It finished the four tasks in 9 min 35 s, against 361 min for the team without Claude, and wrote 1,045 lines of code, against 10,309 for the team with Claude. It did not complete the last step, nudging the ball precisely back to the start, which requires correcting each push from the ball's current position: closed-loop control.

Waddle [23] 把这种方式做成了产品：agent 把目标拆成子任务，查看相机画面、编写控制代码，需要时把 VLA 当作工具调用，交付的是一段可以运行、可以通过对话继续修改的程序。其演示包括叠 T 恤、插入 USB 接头、用子 agent 协调多台机器人，以及一夜之间自主完成约 1,000 次乐高抓放，再用这些数据从头训练一个 ACT 策略。Astranomy [29] 的 agent 模式也属于这一类：GPT-6 Astra 在持续的 Codex 会话中编写代码、调用工具，这是该研究中效果最好的设置（见第 2 节）。

Waddle [23] turns this approach into a product. Its agent splits a goal into subtasks, looks at the camera feeds, writes control code and calls VLAs as tools when needed; what it delivers is a program that runs and can be refined through conversation. Its demonstrations include folding a T-shirt, inserting a USB connector, subagents coordinating several robots, and about 1,000 autonomous overnight LEGO pick-and-places whose data were then used to train an ACT policy from scratch. Astranomy's [29] agent mode belongs here too: GPT-6 Astra writes code and calls tools in a persistent Codex session, the best-performing setting in that study (Section 2).

5语言模型编排 Learned PolicyLanguage models orchestrating learned policies

当 Learned Policy 能够理解语言指令后，Skill Library 就可以替换为一个通用的低层策略，语言模型的角色随之变为 Orchestrator。AutoRT [7] 是较早的大规模尝试：VLM 描述场景，语言模型提出任务，再用一套“机器人宪法”过滤掉不安全或不可行的任务，然后分派给 teleoperator 或自主策略执行。系统最多同时调度 20 台机器人，在多栋楼宇中收集了 7.7 万条真机 episode，覆盖 6,650 条不同的指令。

Once learned policies can follow language, the skill library can be replaced by one general low-level policy, and the language model becomes an orchestrator. AutoRT [7] was an early large-scale attempt: a vision-language model describes the scene, a language model proposes tasks, a “robot constitution” filters out unsafe or infeasible ones, and the tasks are dispatched to teleoperators or autonomous policies. The system ran up to 20 robots at once and collected 77,000 real-robot episodes across several buildings, covering 6,650 distinct instructions.

2025 年的工业系统普遍采用快慢两层的结构。Figure 的 Helix [8] 中，System 2 是一个 7B 参数的 VLM，以 7–9 Hz 运行，负责理解场景和语言；System 1 是一个 80M 参数的 Visuomotor Policy，以 200 Hz 输出整个上半身的动作；两者端到端训练，System 2 通过一个隐向量把意图传给 System 1。Physical Intelligence 的 Hi Robot [9] 用高层 VLM 理解开放式指令，以及执行过程中用户的插话和纠正，把它们转换成简单的语言命令交给 π0 执行，在收拾餐桌、做三明治和买杂货等任务上进行了验证。

Industrial systems in 2025 widely adopted a fast–slow two-level design. In Figure's Helix [8], System 2 is a 7B-parameter vision-language model running at 7–9 Hz that understands the scene and language, and System 1 is an 80M-parameter visuomotor policy that outputs actions for the whole upper body at 200 Hz; the two are trained end to end, with System 2 passing its intent to System 1 as a latent vector. Physical Intelligence's Hi Robot [9] uses a high-level VLM to interpret open-ended instructions as well as the user's interjections and corrections during execution, turning them into simple language commands for π0; it was tested on table bussing, sandwich making and grocery shopping.

Google DeepMind 的 Gemini Robotics 1.5 [11] 把这种分工明确为两个模型：Embodied Reasoning 模型 ER 1.5 负责规划、估计任务进度，并能原生调用 Google 搜索等工具；VLA 模型 Gemini Robotics 1.5 接收每一步的自然语言指令并执行，执行前也会先生成推理过程。官方给出的例子是让机器人先上网查询当地的垃圾分类规则，再把物品分进对应的桶。2026 年的 Gemini Robotics 2 [19] 延续了这一结构，同时发布了 VLA、ER 2 和可在机器人本地运行的 On-Device 2 三个模型，其中 ER 2 通过 Gemini API 公开。

Google DeepMind's Gemini Robotics 1.5 [11] makes this division explicit as two models. The embodied-reasoning model ER 1.5 plans, estimates task progress and can natively call tools such as Google Search; the VLA model Gemini Robotics 1.5 receives a natural-language instruction for each step and executes it, generating its reasoning before acting. The official example has the robot look up local recycling rules online before sorting items into the right bins. Gemini Robotics 2 [19] in 2026 keeps this structure and releases three models together, the VLA, ER 2 and On-Device 2 that runs on the robot, with ER 2 public through the Gemini API.

Policy Supervision 的关键问题是：上层模型的介入到底是增益还是干扰。[17] 发现，模型监督 VLA 时，组合系统的表现仍略低于 VLA 单独运行。较早的模型会抵消 VLA 的大部分能力；最新的模型能识别哪些提议的动作会失败、不再盲目服从，因而恢复了大部分性能，并在 VLA 单独做不到的任务上带来净增益。

The key question for policy supervision is whether the upper model helps or interferes. [17] found that a model supervising a VLA still did slightly worse than the VLA alone. Older models erased most of the VLA's value; the latest models recognize which proposed actions will fail and stop deferring blindly, recovering most of the performance and adding net value on tasks the VLA cannot do alone.

6通用模型作为机器人策略General-purpose models as robot policies

Direct Control 是最接近“把语言模型当作策略”的设置：模型在每一步接收相机图像和机器人状态，输出末端目标、关节力矩或 Action Chunk，下层只剩底层控制器。由于没有预训练技能或 VLA 兜底，这一设置最直接地检验模型自身的空间理解和闭环控制能力，也最受推理延迟的影响。

Direct control is the setting closest to treating a language model as a policy: at every step the model receives camera images and the robot's state and outputs end-effector targets, joint torques or action chunks, with only a low-level controller below it. With no pretrained skills or VLA to fall back on, this setting tests the model's own spatial understanding and closed-loop control most directly, and it is the most affected by inference latency.

[17] 在多种机器人上系统地测试了这一接口。在倒立摆等经典控制任务上，模型直接选择每一步施加的力或力矩；在四足机器人上，较新的模型已能完成有限但有意义的站立、平衡和行走；在机械臂上，较新的模型更擅长接近物体、建立接触和抓取，但完整完成任务的比例只有 0–5.5%。

[17] tested this interface systematically across robots. On classic control tasks such as balancing an inverted pendulum, the model chooses the force or torque to apply at each step. On quadrupeds, newer models achieve limited but meaningful standing, balancing and walking. On arms, newer models are better at reaching objects, making contact and grasping, yet complete the full task only 0–5.5% of the time.

Robocurve 用开源的 Inspect Robots Harness 做了一组第三方真机对比 [21, 22]：模型控制两台 YAM 机械臂，每一轮接收三路相机图像、记录自己的笔记并给出末端目标，每次试验由人工按 0–4 级打分。在“把红色方块放进碗里”的任务上，Claude Fable 5 在 20 次中成功 1 次，Fable 5.1 成功 8 次，GPT-6 Astra 成功 19 次，后者每次约用 2.5 分钟、成本约 0.94 美元；而在“把拼图块插进对应凹槽”的任务上，三个模型都停在最后的插入步骤，最好的结果也只是 20 次中成功 2 次。媒体报道中“Fable 5.1 抓放成功率从 5% 提升到 40%”的数字就来自这项评测，而不是 Anthropic 的发布。

Robocurve ran a set of third-party real-robot comparisons with the open Inspect Robots harness [21, 22]. The model controls two YAM arms; each turn it receives three camera views, keeps its own notes and outputs end-effector targets, and a human grades every trial on a 0–4 scale. On placing a red block in a bowl, Claude Fable 5 succeeded in 1 of 20 trials, Fable 5.1 in 8 and GPT-6 Astra in 19, the last at about 2.5 minutes and $0.94 per run. On inserting a puzzle piece into its groove, all three models stalled at the final insertion, with at best 2 successes in 20. The “Fable 5.1 raised pick-and-place success from 5% to 40%” figure in press coverage comes from this evaluation, not from Anthropic.

Astranomy [29] 在仿真的 DROID 机器人（RoboLab-120）上评测 GPT-6 Astra，直接输出末端动作的成功率为 66.3%，平均每次调用约 18.6 秒。Claude Fable 5.2 的发布报告 [32] 称，模型在 RoboDojo 仿真双臂基准上取得 64.9%，高于 Opus 5.5（39.4%）、Gemini 4 Argon（34.2%）和 GPT-6 Astra（29.8%），这些分数均由 Anthropic 在同一 Harness 上内部测得。报告还展示了真机解魔方、拧瓶盖和画画的演示，但没有说明所用硬件和控制方式，因此无法判断这些演示属于 Direct Control，还是借助了程序或预训练策略。

Astranomy [29] evaluated GPT-6 Astra on a simulated DROID robot (RoboLab-120): emitting end-effector actions directly succeeded 66.3% of the time, at about 18.6 s per call. The Claude Fable 5.2 launch report [32] states that the model reaches 64.9% on the RoboDojo simulated two-arm benchmark, above Opus 5.5 (39.4%), Gemini 4 Argon (34.2%) and GPT-6 Astra (29.8%), all run internally by Anthropic on the same harness. The report also shows real-robot demonstrations of solving a puzzle cube, unscrewing a bottle cap and drawing, but does not describe the hardware or control method, so it is unclear whether the demonstrations used direct control or relied on programs or pretrained policies.

7System 2 足够强时，System 1 和 System 0 会怎样What happens to System 1 and System 0 when System 2 is strong enough

第 3–6 节按接口归类了现有工作。也可以按功能把控制栈分成三层：System 2 负责理解与规划；System 1 生成动作目标或参考轨迹；System 0 是 Low-Level Controller，利用机器人状态反馈，将上层目标转换成位置、速度或力矩等执行器指令。它可以采用机械臂／夹爪的伺服或阻抗控制、四足步态控制、人形全身运动跟踪等实现；既可以基于模型设计，也可以通过学习获得，并可按任务需要使用力觉或视觉反馈。

Sections 3–6 classified existing work by interface. A functional view separates three roles: System 2 handles understanding and planning; System 1 generates action targets or reference trajectories; System 0 is a low-level controller that uses robot-state feedback to convert those targets into actuator commands such as position, velocity or torque. Implementations include arm / gripper servo or impedance control, quadruped gait control and humanoid whole-body tracking. Controllers may be model-based or learned, with force or visual feedback where the task requires it.

图 8 以人形机器人为例：VLM 接收语言和 Ego-Vision，Action Head 通过 Cross-Attention 读取其特征，并输出 Future Kinematics；低层控制器再执行这些参考。Figure 的 Helix 02 [8] 和 SONIC 这类 General Motion Tracker [13] 提供了具体案例。Whole-Body Tracking 是 System 0 的一种实现，不是这一层的通用名称；三层命名也不意味着所有机器人都采用相同的模型或接口。

Figure 8 illustrates a humanoid stack: a VLM takes language and egocentric vision, an action head reads its features through cross-attention and outputs future kinematics, and a low-level controller executes those references. Figure's Helix 02 [8] and general motion trackers such as SONIC [13] provide concrete examples. Whole-body tracking is one implementation of System 0, rather than the general name of that layer; the three-layer terminology does not imply identical models or interfaces across robots.

斯坦福 TML 的 HomeBody [25] 在 GPT-6 Astra 发布后不久提出了一个直接的问题：System 2 能否直接编排一个可复用的运动 Skill Library，而不需要中间那个学出来的 VLA？它用 Astra 作为可替换的高层模型。机器人先自主探索一间陌生的厨房，再由 Astra 担任 Real2Sim Agent，在 Isaac Sim 中重建 Digital Twin，作为持久的空间记忆；之后 Astra 从一个共享接口的 Skill Library（导航、抓取、放置、开抽屉、从抽屉取物）中选择技能和目标。这些技能用经典方法实现，包括基于分割几何的抓取预测、Minimum-Jerk Spline、IK 和碰撞检查；底层由预训练的 AMO Whole-Body Controller 保持平衡，手臂和手的指令以 250 Hz 运行，AMO 策略以 50 Hz 更新。技能失败时，结果会返回给 Astra，由它重新定位或重新规划。系统在 Unitree G1 上完成了“整理厨房”和“取药”两个长时程任务（图 9）。

HomeBody [25], from Stanford's TML and released shortly after GPT-6 Astra, asks a direct question: can System 2 orchestrate a library of reusable motor skills without a learned VLA in between? It uses Astra as a swappable high-level model. The robot first explores an unseen kitchen; Astra then acts as a Real2Sim agent and rebuilds a digital twin in Isaac Sim that serves as persistent spatial memory; afterwards Astra chooses skills and targets from a library with a shared interface (navigate, pick, place, open drawer, pick from drawer). The skills are implemented classically, with grasp prediction from segmented geometry, minimum-jerk splines, inverse kinematics and collision checks, while a pretrained AMO whole-body controller keeps balance: arm and hand commands run at 250 Hz and the AMO policy updates at 50 Hz. When a skill fails, the result goes back to Astra, which repositions or replans. On a Unitree G1 the system completed two long-horizon tasks, tidying a kitchen and retrieving medicine (Figure 9).

HomeBody 证明的是：对于可以分解为离散、准静态技能的长时程任务，学出来的 System 1 可以被“System 2 加 Skill Library”替代。但它没有取消 System 1 的功能，即把语义决策转换成可执行的运动目标，只是把这一功能从一个端到端模型变成了一组显式的程序；System 0 也没有消失，反而承担了全部的平衡与动态协调。论文自己列出的局限也标出了边界：Astra 的推理延迟让技能之间出现停顿；技能演示视频大多被加速压缩到 7–10 秒，从抽屉取物的重试片段以 14 倍速播放；抓取和开抽屉都有重试；页面没有给出成功率。

What HomeBody shows is that, for long-horizon tasks that decompose into discrete, quasi-static skills, a learned System 1 can be replaced by System 2 plus a skill library. It does not remove System 1's function, turning semantic decisions into executable motion targets; it moves that function from an end-to-end model into explicit programs. Nor does System 0 disappear; it carries all of the balance and dynamic coordination. The limitations the authors list mark the boundary: Astra's reasoning latency causes pauses between skills, most skill videos are sped up to fit about 7–10 seconds (the drawer-pick retries play at 14× speed), grasps and drawer opening needed retries, and no success rates are reported.

据此，System 2 变强之后，System 1 可能有三种去向。第一，对于几何上可以描述清楚的准静态技能，它被 Skill Library 和经典规划取代（HomeBody 的路线），而这个 Skill Library 本身可以由 Coding Agent 编写和维护（Waddle [23]、Project Fetch [16]）。第二，对于接触密集、需要视觉闭环的技能（插接、Deformable Object、动态操作），学出来的策略仍然不可替代，但会从一个包揽一切的通用 VLA 变成一组可调用的专门技能，由 System 2 负责组合，Gemini Robotics 的 ER 模型编排 VLA [11, 19] 和 Waddle 都是这种结构。第三，System 2 不再在线控制 System 1，而是为它合成训练数据：Zero-HLM [31] 用 Agent 重建的场景生成了 4,800 条经物理验证的示范，只用这些仿真数据训练的 GR00T N1.7 在三个 Unitree G1 任务上的完整成功率为 66.7%，高于用真实数据训练的 46.7%。这对应图 8 中“扩大 System 1 的数据合成规模”这一问题。

This suggests three possible fates for System 1 as System 2 gets stronger. First, for quasi-static skills that can be described geometrically, it gives way to a skill library and classical planning (HomeBody's route), and that library can itself be written and maintained by coding agents (Waddle [23], Project Fetch [16]). Second, for contact-rich skills that need visual closed loops (insertion, deformable objects, dynamic manipulation), learned policies remain irreplaceable, but they shift from one all-purpose VLA to a set of callable specialist skills composed by System 2, as in Gemini Robotics' ER model orchestrating its VLA [11, 19] and in Waddle. Third, System 2 stops controlling System 1 online and instead synthesizes its training data: Zero-HLM [31] generated 4,800 physically validated demonstrations from agent-reconstructed scenes, and a GR00T N1.7 policy trained only on that simulation data reached 66.7% full-task success on three Unitree G1 tasks, above the 46.7% of a policy trained on real data. This corresponds to the question of scaling up data synthesis for System 1 in Figure 8.

System 1 与 System 0 之间的接口同样关键。图 8 中有两个问题指向它：一是 System 1 需要在推理时适配具体的 System 0，否则它给出的运动学目标可能超出跟踪器的能力；二是用显式的运动学轨迹通信会妨碍技能组合，例如边走边搬、推门的同时迈步时，不同技能给出的目标会相互冲突。可能的方向包括让 System 1 输出 System 0 能直接理解的隐式表示，例如 SONIC 的 Universal Motion Token [13]，或在训练中让两层相互适应，例如 Zero-HLM 用仿真回放的反馈修正 Whole-Body Reference [31]。

The interface between System 1 and System 0 matters just as much. Two questions in Figure 8 point to it. First, System 1 must adapt to the specific System 0 at inference time; otherwise its kinematic targets may exceed what the tracker can follow. Second, communicating through explicit kinematic trajectories hinders skill composition: when walking while carrying, or stepping while pushing a door, targets from different skills conflict. Possible directions include having System 1 output an implicit representation that System 0 understands directly, such as SONIC's universal motion tokens [13], or making the two layers adapt to each other during training, as Zero-HLM does by correcting whole-body references from simulated rollouts [31].

System 0 在这种演化中变得更重要，而不是更不重要：System 2 的能力到不了毫秒级的物理交互，上面各层最终都依赖它的稳健性。图 8 对 System 0 提出了三点要求。其一，要有感知，而不是盲跟踪：PHP [15] 用深度相机让人形机器人根据障碍调整跑酷动作，攀爬墙面或梯子等接触密集的任务同样需要看到接触面。其二，要能控制动力学，而不只是复现运动学：推、拉、搬运和攀爬都与环境交换力，纯运动学跟踪无法表达。其三，一组专家可能比单个模型更好：PHP 先为每种技能训练 Motion Tracking Expert，再蒸馏成一个学生策略；图 8 更进一步，认为单体 Whole-Body Tracker 的表现和扩展性不如一组 System 0 专家。换句话说，System 0 也在走向“Skill Library”，只是它的技能是学出来的，而不是写出来的。

System 0 becomes more important in this evolution, not less: System 2's abilities do not reach millisecond-scale physical interaction, so every layer above ultimately depends on System 0's robustness. Figure 8 places three demands on it. It should perceive rather than track blindly: PHP [15] uses a depth camera so a humanoid adapts its parkour motions to obstacles, and contact-rich tasks such as climbing walls or ladders likewise need to see contact surfaces. It should control dynamics, not just reproduce kinematics: pushing, pulling, carrying and climbing all exchange forces with the environment, which pure kinematic tracking cannot express. And a set of experts may beat a single model: PHP trains a motion-tracking expert per skill and distills them into one student policy, and Figure 8 goes further, holding that a monolithic whole-body tracker performs and scales worse than an ensemble of System 0 experts. In other words, System 0 is also turning into a skill library, only its skills are learned rather than written.

综合来看，System 2 变强之后，三层结构不会坍缩成一层，而是重新分工：System 2 接管任务分解、记忆和工程工作；System 1 碎片化为由程序和学习策略组成的 Skill Library，其训练数据越来越多地由 System 2 合成；System 0 需要变得更通用、能感知、能处理动力学。研究重点随之转向层间接口：System 2 交给下层的是什么（技能调用、目标、隐式 token 还是代码），下层又如何把执行结果和失败信号报告回来。

Taken together, a stronger System 2 does not collapse the stack into one layer; it redistributes the work. System 2 takes over task decomposition, memory and engineering. System 1 fragments into a library of programs and learned policies whose training data is increasingly synthesized by System 2. System 0 must become more general, perceptive and dynamics-aware. The research focus shifts to the interfaces between layers: what System 2 hands down (skill calls, targets, implicit tokens or code) and how the lower layers report execution results and failures back up.

8System 2 越来越强，Direct Control 仍然太慢：一个辩证的分析A stronger System 2 that is still too slow for direct control: a dialectical analysis

正题：System 2 的控制能力在快速提升。在同一套 Inspect Robots 框架下，放方块入碗的成功次数从 Fable 5 的 1/20、Fable 5.1 的 8/20 升到 GPT-6 Astra 的 19/20，前后只隔几个月 [21, 22]；Fable 5.2 在 RoboDojo 仿真上的成绩是 Fable 5.1 的两倍多 [32]；[17] 也观察到，较新的模型在低层控制上有可测的进步。照这个趋势，一个自然的推论是：只要模型再快一些，System 2 就可以直接控制机器人，下面两层可以逐渐取消。

Thesis: System 2's control ability is improving fast. On the same Inspect Robots harness, successes on the block-into-bowl task rose from 1/20 for Fable 5 and 8/20 for Fable 5.1 to 19/20 for GPT-6 Astra within a few months [21, 22]; Fable 5.2 more than doubled Fable 5.1's score on RoboDojo Sim [32]; and [17] also observes measurable gains in low-level control in newer models. The natural extrapolation is that once models get a little faster, System 2 could control robots directly and the two lower layers could gradually be dropped.

反题：延迟是结构性的，不只是工程问题。第一，时间尺度的差距太大（表 2）：前沿模型每次决策需要数秒到数十秒（Astranomy 直接模式约 18.6 秒 [29]），而 HomeBody 的手臂指令以 250 Hz 运行、Whole-Body Controller 以 50 Hz 更新 [25]，Helix 的 System 1 以 200 Hz 输出动作 [8]；即使推理再快一百倍，也仍比接触与平衡所需的反馈慢一到两个数量级。第二，能力与延迟同向增长：推理越充分，消耗的 token 越多，Astranomy 中效果最好的 agent 模式每回合要 3,090 万 token [29]，HomeBody 也报告了技能之间的停顿 [25]。第三，从控制理论看，回路延迟限制了可达到的带宽和稳定裕度，再好的决策也无法纠正比自身决策周期更快的扰动；Project Fetch 推球失败、Robocurve 插槽任务卡在最后一步 [16, 22]，都发生在需要快速反馈修正的环节。第四，云端推理还带来网络、成本和可靠性问题。

Antithesis: the latency is structural, not just an engineering problem. First, the gap in timescales is too large (Table 2): a frontier model needs seconds to tens of seconds per decision (about 18.6 s in Astranomy's direct mode [29]), while HomeBody's arm commands run at 250 Hz and its whole-body controller updates at 50 Hz [25], and Helix's System 1 acts at 200 Hz [8]. Even a hundredfold speedup would leave the model one to two orders of magnitude slower than the feedback that contact and balance require. Second, capability and latency grow together: more thorough reasoning consumes more tokens; Astranomy's best-performing agent mode used 30.9 million tokens per episode [29], and HomeBody reports pauses between skills [25]. Third, in control-theoretic terms, loop delay limits the achievable bandwidth and stability margin: no decision, however good, can correct disturbances faster than its own cycle. Project Fetch's ball nudging and Robocurve's final insertion both failed exactly where fast corrective feedback was needed [16, 22]. Fourth, cloud inference adds network, cost and reliability problems.

合题：不让 System 2 进入快回路，而是改变它输出什么、何时输出。解决这一矛盾的方向不是把 System 2 做得快到能直接控制，而是让它往两个方向移动：向上，输出有效期更长的东西（目标、技能调用、约束、程序）；向外，离开在线控制回路，进入开发回路，为下层构建环境、数据和策略。具体可以分为六条路线。

Synthesis: keep System 2 out of the fast loop and change what it outputs and when. The contradiction is resolved not by making System 2 fast enough to control, but by moving it in two directions: up, toward outputs that stay valid longer (goals, skill calls, constraints, programs); and out of the online control loop into the development loop, where it builds environments, data and policies for the layers below. Six concrete routes follow.

  1. 分时标分层Timescale separationSystem 2 只做慢决策，下层负责快反应；关键是让 System 2 的每一次输出都能管得足够久。Helix 的 7–9 Hz System 2 指挥 200 Hz 的 System 1 [8]，Gemini Robotics 的 ER 模型逐步给 VLA 下指令 [11, 19]。System 2 makes only slow decisions and the lower layers react fast; the key is that each System 2 output stays useful long enough. Helix's 7–9 Hz System 2 directs a 200 Hz System 1 [8], and Gemini Robotics' ER model instructs its VLA step by step [11, 19].
  2. 写控制器，而不是当控制器Write the controller instead of being it一次推理生成一段可以高频运行的程序，把延迟摊到成千上万个控制步上。Code as Policies [4]、Project Fetch [16] 和 Waddle [23] 都属于这一思路，[17] 中模型还可以自己用 RL 训练控制器。局限是写死的程序难以应对未建模的接触动力学。One inference produces a program that runs at high rate, amortizing the latency over thousands of control steps. Code as Policies [4], Project Fetch [16] and Waddle [23] follow this idea, and in [17] the model can even train its own controller with RL. The limit is that fixed programs struggle with unmodeled contact dynamics.
  3. 进入开发回路Move into the development loop让 System 2 在仿真中为下层构建环境、生成数据、训练和修复策略，把延迟从控制时间（毫秒）挪到开发时间（小时）。RoboSimStudio 约一小时从手机视频搭出含 Deformable Object 的仿真 [28]，Zero-HLM 用重建场景训练的策略超过了真实数据训练的策略 [31]，F4R 把真实失败重建成仿真环境来改进 VLA [26]。第 9 节详细讨论。System 2 builds environments, generates data and trains or repairs policies in simulation for the lower layers, moving the latency from control time (milliseconds) to development time (hours). RoboSimStudio builds a simulation with deformables from a phone video in about an hour [28], Zero-HLM's policy trained in reconstructed scenes beats one trained on real data [31], and F4R rebuilds real failures as simulation environments to improve a VLA [26]. Section 9 covers this in detail.
  4. 异步与事件触发Asynchronous, event-triggered calls下层持续执行，System 2 在后台思考，只在子任务完成、失败或不确定性升高时介入。HomeBody 把每次技能执行的结果返回给 Astra [25]；PI 的实时分块（RTC）在执行当前 Action Chunk 的同时生成下一块 [10]，是同一思想在 System 1 层面的实现。The lower layers keep executing while System 2 thinks in the background, stepping in only when a subtask finishes, fails or uncertainty rises. HomeBody returns each skill's result to Astra [25]; PI's real-time chunking (RTC) generates the next action chunk while the current one executes [10], the same idea applied at the System 1 level.
  5. 蒸馏与端侧化Distillation and on-device models把 System 2 的决策蒸馏到更小、更快、能在机器人上运行的模型。Helix 的 7B System 2 完全在机载 GPU 上运行 [8]，Gemini Robotics 2 发布了本地运行的 On-Device 模型 [19]；Robocurve 的对比也显示，新模型完成同一任务所用的 token 和时间都在下降（GPT-6 Astra 每次约 2.1k 输出 token、2.5 分钟，Fable 5.1 约 12.9k、6.8 分钟）[22]。Distill System 2's decisions into smaller, faster models that run on the robot. Helix's 7B System 2 runs entirely on onboard GPUs [8], and Gemini Robotics 2 ships an On-Device model that runs locally [19]; Robocurve's comparisons also show newer models using fewer tokens and less time per task (GPT-6 Astra about 2.1k output tokens and 2.5 minutes per run, Fable 5.1 about 12.9k and 6.8 minutes) [22].
  6. 更好的层间接口Better interfaces between layers让 System 2 的慢输出携带足够的结构，使下层能长时间自主执行：例如隐式动作 token（SONIC [13]）、代价或目标函数、约束条件，而不是逐步的语言指令或显式运动学轨迹（对应图 8 中“显式通信会妨碍技能组合”的问题）。Give System 2's slow outputs enough structure for the lower layers to act autonomously for longer: implicit motion tokens (SONIC [13]), cost or goal functions, or constraints, rather than step-by-step language or explicit kinematic trajectories (the composability problem flagged in Figure 8).

这几条路线的共同点是：System 2 的价值越来越多地体现在构建和组织下层，而不是亲自执行。反过来也要看到两点限制。第一，开发回路本身也有时间成本：RoboSimStudio 搭建一个场景约需一小时 [28]，对于需要在几分钟内适应新情况的部署仍然太慢。第二，越依赖下层，系统的能力上限就越受下层覆盖范围的限制，这又回到了第 2 节的取舍。这个平衡点会随着推理速度和 Coding Agent 能力的提升而移动，但短期内不会消失。

What these routes share is that System 2's value lies increasingly in building and organizing the lower layers rather than executing itself. Two limits remain. First, the development loop costs time too: RoboSimStudio needs about an hour per scene [28], still too slow for deployments that must adapt within minutes. Second, the more a system relies on its lower layers, the more its ceiling is bounded by what those layers cover, which brings back the trade-off of Section 2. The balance point will move as inference gets faster and coding agents get better, but it will not disappear soon.

9Agent 作为机器人工程师：Agentic Real2SimAgents as robotics engineers: Agentic Real2Sim

第 4 节和第 8 节都指向同一个趋势：Coding Agent 已经能完成机器人工程师工作流中相当大的一部分。Project Fetch 第二期中，Claude Opus 4.7 用 9 分 35 秒完成了人类组 361 分钟的工作 [16]；Waddle 在约 20 分钟内写出可用的操作策略 [23]。在这些工作中，杠杆最大的一环是从真实世界构建仿真（Real2Sim）：过去需要人工建模资产、标定相机、调整物理参数，现在可以交给 Agent。Yanjie Ze 维护的论文列表 [33] 中，仅 2026 年 7 月到 11 月初就收录了 39 篇“Agent × Real2Sim2Real”的工作。

Sections 4 and 8 point to the same trend: coding agents can already do a large part of a robotics engineer's workflow. In phase two of Project Fetch, Claude Opus 4.7 did in 9 min 35 s what took a human team 361 minutes [16], and Waddle writes a working manipulation policy in about 20 minutes [23]. The step with the most leverage is building simulations from the real world (Real2Sim), which used to require hand-modeling assets, calibrating cameras and tuning physical parameters and can now be delegated to agents. Yanjie Ze's curated list [33] already counts 39 “agent × Real2Sim2Real” papers between July and early November 2026 alone.

从视频重建多物理场景，包括 Deformable Object。RoboSimStudio [28] 由 UC Berkeley AUTOLab 与 NVIDIA 的 Newton 团队合作完成。输入是一段手机拍摄的机器人操作视频和一句提示，Claude Code 或 Codex 在约一小时内搭出场景、相机和物理，得到一个多物理仿真：刚体在 Newton 中模拟，海绵等 Deformable Object 用 SuperDex 的有限元求解器模拟，两者耦合；人和 Agent 再对照视频调整参数。作者用它构建了 18 个接触密集的操作仿真，涵盖刚体、铰接机构、线缆、布料和软体；在仿真中随机化参数和布局改进策略后，部署到真机完成擦吧台、撕膜和走线缆等任务（图 10）。Agentic Real2Sim [20] 用 VLM Agent 把一段真实的物体–机器人交互录像转成可仿真的“Episodic Twin”，覆盖刚体操作、Deformable Object 和人形运动三类场景，并称以开源 VLM 作为决策后端时，可以用远低于前沿模型的成本达到相近的转换成功率。

Multi-physics scenes from video, including deformables. RoboSimStudio [28] comes from UC Berkeley's AUTOLab and NVIDIA's Newton team. Given a phone video of a robot task and a one-line prompt, Claude Code or Codex builds the scene, camera and physics in about an hour, producing a multi-physics simulation in which rigid bodies run in Newton and deformables such as a sponge run in SuperDex's finite-element solver, coupled together; humans and agents then tune the parameters against the video. The authors built 18 contact-rich manipulation simulations covering rigid bodies, articulated mechanisms, cables, cloth and soft bodies, improved policies in simulation with randomized parameters and layouts, and deployed them on a real robot for tasks such as wiping a bar, peeling film and routing a cable (Figure 10). Agentic Real2Sim [20] uses vision-language agents to turn a real recording of object–robot interaction into a simulatable episodic twin, covering rigid manipulation, deformable objects and humanoid motion, and reports that an open-weight VLM as the decision backend reaches comparable conversion success at a small fraction of a frontier model's cost.

从机器人演示数据构建可交互世界。WorldMirror [30] 把 Real2Sim 视为对一个可执行“World Program”的迭代修改：Coding Agent 规划重建步骤，调用图像和 3D 生成工具，并根据验证反馈纠错；它在 DROID 数据上重建的世界既保留了视觉外观，也保持了演示轨迹的物理有效性。

Interactive worlds from robot demonstrations. WorldMirror [30] treats Real2Sim as iterative refinement of an executable world program: a coding agent plans reconstruction steps, calls image and 3D generation tools and corrects errors from verification feedback; on DROID it rebuilds worlds that keep both the visual appearance and the physical validity of the recorded trajectories.

为下层合成数据和策略。Zero-HLM [31] 从手机拍摄重建场景，并用仿真回放的反馈修正 Whole-Body Reference，生成 4,800 条经物理验证的示范，训练出的人形策略 Zero-Shot 迁移到真机（见第 7 节）。Agentic RSR [27] 先由 Agent 在 MuJoCo 中重建工作台并检查交互，再由 Coding Agent 在仿真中开发策略，真机的总体成功率达到仿真成功率的 80%。F4R [26] 让 Agent 从真实部署中识别失败，把每次失败重建成交互式仿真环境，通过 Sim–Real Co-training 和定向 RL 改进 VLA，在四个真实任务上达到 93.75%（分布内）和 90.0%（分布外）的成功率。

Data and policies for the lower layers. Zero-HLM [31] reconstructs scenes from phone captures and corrects whole-body references from simulated rollouts, generating 4,800 physically validated demonstrations whose trained humanoid policy transfers zero-shot to the real robot (Section 7). In Agentic RSR [27], an agent first rebuilds the workspace in MuJoCo and checks interactions, then a coding agent develops the policy in simulation; real-robot success reaches 80% of simulated success. F4R [26] has an agent identify failures in real deployment, rebuild each as an interactive simulation environment and improve a VLA through failure-conditioned sim–real co-training and targeted RL, reaching 93.75% in-distribution and 90.0% out-of-distribution success on four real tasks.

为 System 2 提供空间记忆。HomeBody [25] 用 Astra 作为 Real2Sim Agent，从人形机器人自己采集的探索数据在 Isaac Sim 中构建厨房的 Digital Twin，让高层模型可以推理视野之外的位置。

Spatial memory for System 2. HomeBody [25] uses Astra as a Real2Sim agent to build a digital twin of the kitchen in Isaac Sim from the humanoid's own exploration data, so the high-level model can reason about places outside its view.

放回三层架构中看，Agentic Real2Sim 把 System 2 最擅长的能力（编程、推理、使用工具）转化成了 System 1 和 System 0 最需要的东西（训练环境、数据和可验证的策略），而且发生在开发时间而不是控制时间，正好绕开了第 8 节讨论的延迟问题。

Seen through the three-layer architecture, Agentic Real2Sim converts what System 2 does best (programming, reasoning, tool use) into what System 1 and System 0 need most (training environments, data and verifiable policies), and it does so in development time rather than control time, sidestepping the latency problem of Section 8.

这一路线的瓶颈在验证。Agent 可以很快搭出一个“看起来对”的场景，但接触、摩擦和 Deformable Object 的物理是否可信，需要以测量为依据的反馈（RoboSimStudio 同时使用视觉对比和力反馈来校准）；目前大多数 Sim–Real 一致性的结论仍是作者自报，接触密集任务的物理保真度也难以评估。此外，构建一个场景仍需约一小时和不低的模型调用成本，离部署时的在线适应还有距离。

The bottleneck of this route is verification. An agent can quickly build a scene that looks right, but whether its contact, friction and deformable physics are credible requires measurement-grounded feedback (RoboSimStudio calibrates against both visual comparison and force feedback); most sim–real agreement claims so far are self-reported, and the physical fidelity of contact-rich tasks remains hard to assess. Building a scene also still takes about an hour and substantial model costs, far from online adaptation at deployment time.

10评测方法与基准Evaluation methods and benchmarks

这一方向的定量结果高度依赖 Harness：模型能看到什么观测、能调用哪些工具、动作以什么形式输出、允许思考多久，都会显著改变结果。因此，比较不同模型之前需要先固定框架。现有评测大致分为三类（表 3）。

Quantitative results in this area depend heavily on the harness: what the model observes, which tools it can call, what form its actions take and how long it may think all change the outcome substantially. Models therefore need to be compared on a fixed harness. Current evaluations fall roughly into three groups (Table 3).

第一类只测上层编排。Butter-Bench [12] 选择了一种几乎不需要低层 Executor 的机器人形态，以便单独评估语言模型的规划和社交理解能力。第二类测量不同接口下的能力。Anthropic 的 Embody 评测集 [17] 在经典控制、仿真四足与人形、机械臂和真实四足机器人上，分别测试 Direct Control、编写控制器、自行训练 RL 策略和监督预训练策略四种接口，并给出跨机器人的归一化综合分数。第三类是通用的机器人策略基准，被用来在语言模型与专用策略之间做比较。RoboDojo [18] 包含 42 个在 Isaac Sim 中运行的双臂任务（ARX X5 平台）和三种平台上的 18 个真机任务，已接入 30 个策略；作者指出，仿真与真机排行榜只部分一致，一些仿真得分较高的模型在真机上明显变差。Robocurve 的 Inspect Robots [21] 使用真机、固定任务和人工分级打分，并公开每次试验的完整录像和模型记录。NVIDIA 的 RoboLab-120 [29] 则在仿真中比较同一模型的不同使用方式及其成本。

The first group measures only high-level orchestration. Butter-Bench [12] chose a robot form factor that needs almost no low-level executor, so that the language model's planning and social understanding could be assessed on their own. The second group measures ability under different interfaces. Anthropic's Embody suite [17] tests direct control, controller writing, self-run reinforcement learning and policy supervision on classic control, a simulated quadruped and humanoid, an arm and a real quadruped, and reports a normalized composite score across robots. The third group consists of general robot-policy benchmarks used to compare language models with specialized policies. RoboDojo [18] contains 42 two-arm tasks in Isaac Sim (ARX X5 platform) and 18 real tasks on three platforms, with 30 policies integrated; its authors note that the sim and real leaderboards only partly agree, and some models with high sim scores drop sharply on real hardware. Robocurve's Inspect Robots [21] uses real robots, fixed tasks and human stage-based grading, and publishes full recordings and model transcripts of every trial. NVIDIA's RoboLab-120 [29] compares different ways of using the same model in simulation, together with their cost.

11尚未解决的四个问题Four open problems

11.1程序与动作两种输出形式的取舍Programs versus actions

输出程序的优势在于可读、可复用、可以调用工具，而且一次推理可以覆盖多步执行，从而绕开推理延迟。现有对比大多支持这一点：在 Astranomy [29] 中，可以编写代码和调用工具的 agent 模式比直接输出动作高 8.5 个百分点；在 [17] 中，直接驱动关节的表现远低于编写控制器或监督预训练策略。输出动作的优势在于真正的闭环：程序在编写时无法预见所有情况，而逐步输出动作可以对每一次观测作出反应。代价是延迟和成本，这也是 Direct Control 目前主要出现在评测中而不是部署中的原因。Waddle [23] 的设计是一种折中：用代码完成规划和粗粒度控制，把需要快速反馈的部分交给 VLA。

Programs are readable and reusable, can call tools, and let one inference cover many execution steps, sidestepping latency. Existing comparisons mostly support this: in Astranomy [29] the agent mode, which can write code and call tools, beat direct actions by 8.5 percentage points, and in [17] direct joint control fell far behind writing controllers or supervising pretrained policies. The advantage of actions is a true closed loop: a program cannot anticipate every situation when it is written, while step-by-step actions can respond to every observation. The price is latency and cost, which is why direct control so far appears mainly in evaluations rather than deployments. Waddle's [23] design is a compromise: code handles planning and coarse control, and the parts that need fast feedback go to a VLA.

11.2通用模型与专用策略的关系General-purpose models and specialized policies

Anthropic 称 Fable 5.2 在 RoboDojo 上超过了大多数专门为机器人构建的系统 [32]，但这是内部测试结果，而 RoboDojo 的作者也指出仿真与真机排名只部分一致 [18]。Isola [24] 认为，单看能力，语言模型控制的机器人仍远不如专用方案；它真正的优势在于扩散速度：通过云端模型，智能可以在不改动硬件的情况下迅速覆盖大量已有机器人。[17] 的监督实验给出了更细的图景：通用模型目前更适合作为专用策略的上一层，在专用策略做不到的任务上提供增益。

Anthropic says Fable 5.2 outperforms most systems built specifically for robots on RoboDojo [32], but these are internal results, and RoboDojo's own authors note that sim and real rankings only partly agree [18]. Isola [24] argues that, on capability alone, robots controlled by language models are still far behind dedicated solutions; their real advantage is how fast they spread, since a cloud model can bring intelligence to many existing robots without hardware changes. The supervision experiments in [17] give a finer picture: general-purpose models currently fit best as the layer above specialized policies, adding value on tasks those policies cannot do.

11.3成本、可靠性与安全Cost, reliability and safety

延迟之外（第 8 节），云端模型还带来成本和安全问题。成本方面，Astranomy 中 agent 模式每回合约消耗 3,090 万 token、36.40 美元 [29]。安全方面，Project Fetch 第一期中，一台机器狗因速度和距离计算错误，险些撞到另一组参与者 [14]；Isola 指出，向 AI 开放 sensor 和 actuator 接口会带来新的攻击面 [24]。因此 Helix [8] 和 Gemini Robotics 2 的 On-Device 模型 [19] 等工业系统都把快速的低层控制放在机器人本地运行。

Beyond latency (Section 8), cloud models raise cost and safety problems. On cost, Astranomy's agent mode used about 30.9 million tokens, or $36.40, per episode [29]. On safety, in phase one of Project Fetch a robot dog, after a speed and distance miscalculation, nearly struck the other team [14], and Isola points out that opening sensor and actuator interfaces to AI creates a new attack surface [24]. Industrial systems such as Helix [8] and the On-Device model of Gemini Robotics 2 [19] therefore run fast low-level control on the robot itself.

11.4精细闭环控制仍是主要瓶颈Fine closed-loop control remains the bottleneck

Andon Labs 认为，当前“Orchestrator 加 Executor”系统的瓶颈在 Executor 而不在 Orchestrator [12]；但同一基准也显示，前沿模型作为 Orchestrator 只完成了 40% 的任务，主要败在空间推理。2026 年的结果呈现出更清晰的分布：高层规划和 Program Synthesis 进步最快 [16]，而凡是需要根据实时观测精细修正动作的环节，模型普遍失败。Project Fetch 没能把球推回起点，Robocurve 的插槽任务中三个模型都停在最后一步 [22]，[17] 中的模型也无法在没有预训练策略的情况下控制人形机器人。

Andon Labs argues that today's orchestrator-plus-executor systems are bottlenecked by the executor rather than the orchestrator [12]; yet the same benchmark shows frontier models completing only 40% of tasks as orchestrators, failing mainly on spatial reasoning. The 2026 results show a clearer pattern: high-level planning and program synthesis have improved fastest [16], while models generally fail wherever an action must be finely corrected from live observations. Project Fetch could not nudge the ball back to the start, all three models in Robocurve's groove task stalled at the final step [22], and in [17] models could not control a humanoid without a pretrained policy.
